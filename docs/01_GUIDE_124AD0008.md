## Concepts to learn before you start

- **SMILES strings** — a compact text way of writing a molecule. You don't need to become a chemist, just understand that it's text data you can load into Python like any other string column.
- **Amino acid sequences (FASTA-style)** — a protein written as a string of letters (like `MSTNPKPQ...`), one letter per building block. Also just a string column, technically.
- **Cold-start splitting** — instead of randomly mixing all your data into train/test (which lets the same drug or protein appear in both, making the test artificially easy), you deliberately hold out *entire drugs* or *entire proteins* so the test set contains things the model has truly never seen. This is the single most important idea in our whole project — take time to genuinely understand it, since you're the one building it.
- **Binding site annotation** — a database entry that says "for this specific protein, drugs physically attach around amino acid positions 41, 143, 144, 145..." This is our ground truth for checking whether the model's attention is pointing at the right place.
- **A "baseline" model** — an already-published model we run on our exact same data and splits, purely so we have fair numbers to compare ColdSite-DTI against. You are not improving these models, just running them correctly.

**Suggested prep (a few hours, not days):** skim the original DAVIS and KIBA papers' abstracts (just to know what they measured and why), and read through PyTDC's documentation homepage (tdcommons.ai) once before touching code.

## Step 2: Build the four splits

This is the heart of your job. PyTDC supports exactly the splits we need:

```python
# Level 1 — warm / random split (the easy baseline case)
split_random = data.get_split()

# Level 2 — cold-drug (new drug, familiar protein)
split_cold_drug = data.get_split(method='cold_split', column_name='Drug')

# Level 3 — cold-target (familiar drug, new protein)
split_cold_target = data.get_split(method='cold_split', column_name='Target')

# Level 4 — cold-pair (both new — the hardest, most realistic case)
split_cold_pair = data.get_split(method='cold_split', column_name=['Drug', 'Target'])
```

Do this for both DAVIS and KIBA. Save each split (train/valid/test) as CSV files with clear names, e.g. `davis_cold_drug_train.csv`, `davis_cold_drug_test.csv`, and so on — twelve file-sets total per dataset (4 split types × train/valid/test), times two datasets.

**Sanity check that matters:** after building a cold-drug split, actually verify in code that no drug ID appears in both your train and test CSVs. Do this check for every split type. If it fails, the whole paper's core claim is compromised — so check it now, not in October.

**Deliverable:** all split files saved in a clearly organized folder, plus a short table (drugs/proteins/pairs per split, per dataset) posted for the team.

## Step 4: Collect binding-site ground truth

For every unique protein target in DAVIS, KIBA, and your antiviral subset, you need its real, known binding-site residue positions. Two ways to get this, use both for cross-checking:

**Option A — scPDB:** browse/download from `http://bioinfo-pharma.u-strasbg.fr/scPDB` (search by protein name or PDB ID). It gives atom-level binding site data for thousands of protein-ligand complexes.

**Option B — UniProt (most reliable, always accessible):** UniProt has a free REST API. For any protein, you can pull its official "Binding site" and "Active site" annotations as structured data:

```python
import requests

def get_binding_sites(uniprot_id):
    url = f"https://rest.uniprot.org/uniprotkb/{uniprot_id}.json"
    r = requests.get(url)
    data = r.json()
    sites = []
    for feature in data.get('features', []):
        if feature['type'] in ('Binding site', 'Active site'):
            sites.append(feature['location'])
    return sites
```

You will need to map DAVIS/KIBA protein identifiers to UniProt IDs first — DAVIS and KIBA typically use gene/kinase names, so a short lookup table (built by hand for ~379 DAVIS proteins, or reused from a published mapping if you find one) is required. This is fiddly but not hard — budget real time for it, it's the least glamorous part of the whole project and also one of the most important, since 124AD0067's entire evaluation depends on this being correct.

**Deliverable:** one clean file mapping `protein_id → list of known binding-site residue positions`, covering every protein used anywhere in the project. This is arguably your single most important deliverable — hand it to 124AD0067 with a clear readme explaining the format.

## Common mistakes to avoid

- Building splits and forgetting to check for leakage — always verify no train/test ID overlap in code, don't eyeball it.
- Using different protein ID formats across DAVIS, KIBA, UniProt, and scPDB without reconciling them — decide on one ID system early (UniProt accession IDs are a sensible standard) and convert everything to it.
- Spending too long perfecting the antiviral filter — a reasonable keyword-based filter, refined once with 124AD0067, is enough; don't let this become a rabbit hole.
