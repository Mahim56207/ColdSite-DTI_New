## Concepts to learn before you start

- **Interpretability vs. faithfulness (an important distinction):** an explanation can *look* biologically plausible (it points somewhere sensible) without the model actually *relying* on that spot to make its decision. We are mainly testing the first kind here — biological plausibility, checked against real annotated data — which is still a rigorous, meaningful, and currently under-tested claim once we test it under cold-start.
- **Precision@k** — take the model's top-k highest-attention positions on a protein. What fraction of them are genuinely real binding-site positions (from ground-truth annotation)? That fraction is precision@k. Simple idea, and it's the core metric of your whole track.
- **Statistical significance testing** — just checking "6 out of 10 top positions were correct" isn't enough on its own; you also want to know if that's meaningfully better than picking 10 random positions would give you by chance. A simple permutation test (explained below) answers this.
- **Binding/active site (recap)** — the real physical region on a protein where a drug attaches. Your ground truth for "correct" comes from 124AD0008's UniProt/scPDB data file.

**Suggested prep:** read through the abstracts of the five required-reading papers in the master plan's Section 9 in your first few days — you'll be leading the differentiation write-up, so the sooner you deeply understand what's already been done, the better every later decision on this track will be.

## Step 1: Build the precision@k evaluation function

Test this with made-up random numbers first — you don't need the real model yet.

```python
import numpy as np

def precision_at_k(attention_weights, true_binding_sites, k=10):
    """
    attention_weights: 1D array, one score per protein position
    true_binding_sites: set of position indices that are real binding sites
    k: how many top-attended positions to check
    """
    top_k_positions = np.argsort(attention_weights)[-k:]
    hits = sum(1 for pos in top_k_positions if pos in true_binding_sites)
    return hits / k

# Quick test with fake data before anything real exists:
fake_attention = np.random.rand(300)          # pretend protein of length 300
fake_binding_sites = {41, 42, 43, 143, 144, 145}
print(precision_at_k(fake_attention, fake_binding_sites, k=10))
```

## Step 2: Add a significance check

A permutation test answers: "is this precision@k score better than what pure chance would give?"

```python
def permutation_test(true_binding_sites, protein_length, k=10, n_trials=1000, observed_precision=None):
    random_scores = []
    for _ in range(n_trials):
        random_top_k = np.random.choice(protein_length, size=k, replace=False)
        hits = sum(1 for pos in random_top_k if pos in true_binding_sites)
        random_scores.append(hits / k)
    random_scores = np.array(random_scores)
    p_value = np.mean(random_scores >= observed_precision)
    return random_scores.mean(), p_value
```

## Common mistakes to avoid

- Testing your evaluation code only once, on one lucky example — test it on several dummy cases, including edge cases (e.g., what happens if `k` is bigger than the number of true binding sites?).
- Writing the literature review by lightly rephrasing sentences from the papers — always explain each paper fully in your own words, from your own understanding, not by editing their sentences.
- Treating a "boring" result (fidelity doesn't drop much) as a failure — it's a legitimate, useful, honest finding either way. Don't let the desire for a dramatic result bias how you report the numbers.
